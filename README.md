# cnation STS — 첨탑을 오르다

> **Version 1.3.11**

원작 **Slay the Spire (1편)** 의 규칙을 그대로 재현한 **모바일 세로형 웹 게임**입니다.
스마트폰 브라우저에서 바로 실행되며, 컴퓨터(AI)가 조종하는 몬스터와 1층부터 50층까지 대결합니다.

* 카드/UI : **HTML + CSS + 인라인 SVG** (외부 이미지 파일 0개, 모든 문양은 벡터로 생성)
* 캐릭터/몬스터 : **three.js 절차적 저폴리 모델** (외부 3D 모델·텍스처 0개)
* 효과음 : **WebAudio 합성** (외부 음원 파일 0개)
* 빌드 도구 불필요 — 순수 ES 모듈, 정적 호스팅만으로 동작

## 1. 실행 방법

### 로컬
```bash
# 정적 서버라면 무엇이든 가능합니다
npx serve .            # 또는  npm run dev
python3 -m http.server 8080
```
→ 브라우저에서 `http://localhost:8080` 접속 (모바일 뷰로 보면 가장 자연스럽습니다).

> `file://` 로 직접 열면 ES 모듈 CORS 정책 때문에 동작하지 않습니다. 반드시 서버로 여세요.

### Vercel 배포
정적 사이트라 별도 설정이 필요 없습니다.

```bash
vercel            # 프리뷰
vercel --prod     # 프로덕션
```
* Framework Preset : **Other**
* Build Command : 비움
* Output Directory : `.`

`vercel.json` 에 캐시/보안 헤더가 이미 들어 있습니다.
배포 후 모바일에서 **홈 화면에 추가** 하면 전체화면 앱처럼 실행됩니다 (`manifest.webmanifest` 포함).

## 3. 재현한 원작 규칙

### 층 구조 (요청 사양 그대로)
| 막 | 층 | 보스 |
|---|---|---|
| 1막 | 1 ~ 17층 | **17층 중간 보스** |
| 2막 | 18 ~ 34층 | **34층 중간 보스** |
| 3막 | 35 ~ 50층 | **50층 최종 보스** |

* 중간 보스(17층·34층)를 처치하면 **다음 막을 체력 최대치로 시작**합니다.
* 지도는 원작처럼 분기형이며, 각 막 중간에 보물 방, 보스 직전 행에 모닥불이 고정 배치됩니다.
* 방 종류 : 전투 / 정예 / ? 의문(이벤트) / 모닥불 / 상점 / 보물 / 보스

### 전투 규칙
* 매 턴 에너지 3, 카드 5장 드로우. 손패 최대 10장.
* 방어도는 턴 종료 시 사라짐 (바리케이드·캘리퍼스 예외).
* 피해 계산 순서 : `기본값 + 힘(+활력) → 약화 ×0.75 → 취약 ×1.5 → 내림` 후 방어도 차감.
* **취약** 받는 공격 피해 +50% / **약화** 주는 피해 −25% / **허약** 얻는 방어도 −25%
* **중독**은 해당 액터의 턴 시작에 피해 후 1 감소, **금속화·도금 갑옷·연소·재생**은 턴 종료에 발동.
* **인공물**이 디버프를 1개씩 무효화, **무형**은 받는 피해를 1로, **완충**은 체력 손실 1회 무효.
* 지속시간형 디버프(취약/약화/허약/무형)는 **소유자 턴 종료 시** 1 감소.
* 소각 / 소멸 / 내재 / 보존 / X 비용 / 혼란(무작위 비용) 모두 구현.
* 적의 **의도(Intent)** 를 아이콘 + 예상 피해량(힘·약화·취약 반영)으로 표시. 룬 돔은 의도를 가립니다.
* 분열(슬라임), 형태 변환(수호자), 각성(깨어난 자), 시간 왜곡(시간 포식자), 수하 소환 등 보스 고유 기믹 포함.

### 보상 규칙
* 일반 10~20G / 정예 25~35G / 보스 95~105G
* 카드 보상 3장 (물음표 카드 +1, 부서진 왕관 −2, 기도 바퀴 일반전투 +1)
* 희귀도 롤 : 일반 → 고급 → 희귀, **희귀가 나오면 다음 확률 보정**(원작의 rarity bonus 방식)
* 2막 12.5% / 3막 25% 확률로 보상 카드가 강화 상태로 등장
* 물약 드랍 확률 40% 에서 획득 시 −10%p, 실패 시 +10%p
* 정예 처치 시 유물, 보스 처치 시 **보스 유물 3종 중 택 1**

## 8. 변경 이력

### v1.5.9 — 시작 체력 +10 · 시작 보너스 5개 중 2개 선택

조금 더 캐주얼하게. 두 가지를 바꿨다.

**① 시작 최대 체력 +10** (`js/data/characters.js`)

| 캐릭터 | 전 | 후 |
|---|---|---|
| 아이언클래드 | 80 | **90** |
| 사일런트 | 70 | **80** |
| 디펙트 | 75 | **85** |
| 와쳐 | 72 | **82** |

1막 초반 조정(첫 전투 체력 55%·피해 50%, 두 번째 75%·70%)은 그대로 두었다.
체력만 올렸으므로 중후반 체감이 가장 크게 달라진다.

**② 시작 보너스 : 5개 중 2개** (`js/data/neow.js` · `js/main.js`)

예전에는 네 가지 중 하나였다. 이제 다섯을 내주고 둘을 고른다.

```js
// neow.js — 혜택 4 + 대가 1
export function rollNeowOptions(rng) {
  const benefits = rng.shuffle(NEOW_BENEFITS.slice()).slice(0, 4);
  const drawback = rng.pick(NEOW_DRAWBACKS);
  return rng.shuffle([...benefits, drawback]);
}

// main.js
const NEOW_PICKS = 2;
```

대가가 따르는 것(골드 +250 · 저주 1장 같은 것)은 **언제나 한 자리뿐**이라,
둘 다 대가를 짊어지는 일은 없다. 한 번 고른 것은 목록에서 빠지고 위쪽에 남아
무엇을 집었는지 보이며, 두 번째까지 고르면 결과 두 줄을 한꺼번에 보여 준다.
카드 제거·강화·변환처럼 중간에 카드를 고르는 보너스도 둘 다 정상 동작한다
(아이언클래드·사일런트·디펙트 세 캐릭터로 끝까지 확인).

### v1.5.8 — 전투 중 강제 종료 시 그 전투가 건너뛰어지던 문제

전투 도중 앱을 강제로 닫고 다시 열면 **그 전투가 통째로 없던 일이 되고 다음 층 지도**에서
시작했다. 싸우지도 않았는데 방은 지나간 것으로 처리되고 보상도 사라졌다.

**원인** — 두 군데에서 "이미 방에 들어갔다" 는 상태를 저장하고 있었다.

```js
function enterRoom(pos) {
  const node = run.enterNode(pos);   // 층·방문 표시가 여기서 바뀐다
  …startBattle(…)
  saveRun(run);                      // ← 들어간 뒤 상태를 저장
}
addEventListener('visibilitychange', () => {
  if (document.hidden && G.run) saveRun(G.run);   // ← 앱을 내릴 때 또 저장
});
```

앱을 강제로 닫으면 `visibilitychange` 가 먼저 뜨면서 **전투 중인 상태**가 저장된다.
그런데 저장 형식에는 전투가 담기지 않으므로, 남는 것은 "그 방을 지나왔다" 는 사실뿐이었다.

**고친 방법** — 저장 시점을 바꿨다.

* `enterRoom` : 방에 들어가기 **전**에 저장한다 (들어간 뒤 저장은 없앴다).
* `visibilitychange` : **전투 중에는 저장하지 않는다** (`!G.battle`).

그래서 전투 중에 앱이 죽으면 디스크에는 *그 방 앞* 상태만 남는다. 다시 열면 지도로 돌아오고,
씨앗(`rngSeed`)도 그 시점 그대로라 **같은 전투를 처음부터** 치른다.

상점·모닥불처럼 안에서 무언가를 고르는 방은 고를 때마다 `saveRun` 이 불리므로 그대로다.
보상 화면은 전투가 이미 끝나 `G.battle` 이 비어 있어 평소처럼 저장된다.

| | 전 | 후 |
|---|---|---|
| 전투 중 강제 종료 → 이어하기 | 다음 층 지도 (전투·보상 사라짐) | **그 전투 앞 지도** (다시 싸울 수 있다) |
| 이기고 보상까지 받은 뒤 | 정상 | 정상 (골드 99 → 163 · 방문 1 확인) |

### v1.5.7 — 위쪽 여백 기본값 82px

v1.5.6 으로 보정이 드디어 실제 기기에 닿았고, 그 위에서 **관리자 모드 → 화면 여백 조정**으로
직접 맞춰 보니 `자동 62 + 손 20 = 82px` 이 알맞았다. 그래서 그 값을 기본값으로 올렸다.

```
상단바 82~161 · 물약칸 90~117 · 메뉴 123~155      (아이폰 15 Pro Max 홈 화면 앱)
```

상태바가 59px 이니 **23px 이 숨 쉬는 자리**로 남는다.

> **손조정에는 판 번호가 붙는다.** 손조정은 "그때의 자동값에 얼마를 더했나" 이므로,
> 자동값을 올리면 옛 손조정이 겹쳐 두 배가 된다 (62+20 으로 맞춰 둔 기기가 82+20=102 가 된다).
> `sts.safeAdjustV` 가 그것을 막는다 — 자동값을 바꾼 판에서는 옛 손조정을 **한 번 지운다.**
> 앞으로 자동값을 또 손보면 `VER` 을 올릴 것.

### v1.5.6 — 여백 계산을 js 모듈로 (캐시에 묶인 index.html 이 v1.5.5 를 막고 있었다)

v1.5.5 를 올렸는데 **타이틀 버전만 1.5.5 로 바뀌고 전투 화면은 v1.5.4 와 픽셀까지 같았다.**

**왜 안 먹었나** — v1.5.5 의 계산을 `index.html` 의 인라인 스크립트에 두었다.
iOS 홈 화면 앱은 **시작 문서(index.html)를 캐시에 묶어 두는 일이 있다.**
`js/*.js` 는 새로 받아 오므로 `js/version.js` 의 `1.5.5` 는 보이는데,
정작 여백을 심는 인라인 스크립트는 옛 문서라 아예 없었다 — 그래서 아무 일도 일어나지 않았다.

**고친 방법** — 계산을 `js/safearea.js` 로 옮기고 `js/main.js` 가 맨 먼저 부른다.
`index.html` 에도 같은 값을 심는 사본이 남아 있지만 그건 **깜빡임을 없애려는 덤**이고,
본체는 모듈이다. 캐시에 묶인 문서로 접속하는 상황을 테스트로도 재현해 두었다
(`index.html` 에서 인라인 스크립트를 지운 채 띄워도 `62px` 이 적용된다).

* 위쪽 **62px** — 다이내믹 아일랜드(59px)를 넘어선다.
* **아래쪽은 건드리지 않는다.** 지금도 충분하고, 늘리면 손패가 그만큼 좁아진다.
* 관리자 모드 → **화면 여백 조정** : `− 10 / − 4 / + 4 / + 10` 으로 위쪽 여백을 손수 맞출 수 있다.
  이 기기에만 저장된다(`localStorage`). 자동값이 안 맞는 기기가 또 나오면 그 자리에서 맞추면 된다.

```
상단바 62~141 · 물약칸 70~97 · 메뉴 103~135      (아이폰 15 Pro Max 홈 화면 앱)
```

> **여백 계산을 index.html 에 두지 말 것.** 홈 화면 앱에서 그 파일만 옛것으로 남을 수 있다.
> 고칠 일이 생기면 `js/safearea.js` 를 고친다.

### v1.5.5 — env() 를 버리고 화면 비율로 아이폰 여백을 정한다

v1.5.2 · v1.5.3 · v1.5.4 세 번 고쳤는데 **실제 아이폰에서는 화면이 한 픽셀도 움직이지 않았다.**
v1.5.3 과 v1.5.4 스크린샷을 픽셀로 겹쳐 보니 위쪽 배치가 완전히 같았다.

**왜 안 먹었나** — 세 번 다 `env(safe-area-inset-*)` 을 바탕으로 바닥값을 계산했다.
그런데 그 기기에서 `env(safe-area-inset-bottom)` 이 **0 으로 온다.**
그러면 `min(0 × 3, 62px)` = `0` 이라 바닥값이 통째로 사라진다. 계산식이 아무리 정교해도
**0 을 곱한 것과 같았다.**

**고친 방법** — env 를 아예 쓰지 않는다. `index.html` 의 인라인 스크립트가 **화면 비율**로 판단한다.

```js
var sw = Math.min(screen.width, screen.height);
var sh = Math.max(screen.width, screen.height);
if (sh / sw >= 2.1) {                       // 노치·다이내믹 아일랜드 아이폰
  d.style.setProperty('--safe-t', 'max(env(safe-area-inset-top, 0px), 62px)');
  d.style.setProperty('--safe-b', 'max(env(safe-area-inset-bottom, 0px), 30px)');
}
```

| 기기 | 세로비 | 결과 |
|---|---|---|
| 아이폰 X ~ 16 Pro Max (노치·아일랜드) | 2.16 ~ 2.17 | 위 **62** · 아래 **30** |
| 아이폰 SE · 8 (홈 버튼) | 1.78 | 그대로 |
| 아이패드 | 1.33 | 그대로 |
| 사파리(막대 있음) · 안드로이드 · 컴퓨터 | — | 그대로 (조건 자체가 안 걸린다) |

두 가지를 바꾼 것이 핵심이다.

1. **env 값에 곱하거나 비례하지 않는다.** 0 이 와도 62 는 확보된다 (`max`).
2. **스타일시트가 아니라 화면 요소에 직접 심는다.** 인라인 스타일은 어떤 규칙보다 세고,
   `css/style.css` 가 캐시에 묶여 있어도 반드시 적용된다.

재어 보면 (아이폰 15 Pro Max 홈 화면 앱 기준)

```
상단바 62~141 · 물약칸 70~97 · 메뉴 103~135 · 손패 691~835 · 턴 종료 847~890
```

물약칸이 상태바(59) 아래로 완전히 빠지고, 아래쪽도 홈 인디케이터를 피한다.
관리자 모드 → 이 기기 정보의 **표시 모드**에 `iOS 앱 · 노치 보정 켜짐`, **기기 화면**에
`430×932 · 세로비 2.17` 이 찍히는지로 확인할 수 있다.

### v1.5.4 — 아이폰이 알려 주는 안전 여백을 믿지 않는다

전투 화면에서 **물약칸이 다이내믹 아일랜드에 가려 눌리지 않았다.**
스크린샷(아이폰 15 Pro Max · 1290×2796)을 픽셀로 재어 보니

| | 실제 | 아이폰이 알려 준 값 |
|---|---|---|
| 위 (상태바) | 59px | **약 30px** |
| 아래 (홈 인디케이터) | 34px | **약 22px** |

`black-translucent` 로 설치된 홈 화면 앱은 `env(safe-area-inset-*)` 을 **실제보다 작게** 준다.
v1.5.2 의 `아래 × 1.7` 바닥값도 `22 × 1.7 = 37px` 밖에 안 되어 여전히 모자랐다.

**고친 방법** — iOS 홈 화면 앱에서만 바닥값을 **62px 에서 끊어** 잡는다.

```css
html.ios-app {
  --safe-t: max(env(safe-area-inset-top, 0px),
                min(calc(env(safe-area-inset-bottom, 0px) * 3), 62px));
}
```

| 기기가 알려 주는 값 | 결과 |
|---|---|
| 30 / 22 (값이 작게 오는 아이폰) | `min(66, 62)` → **62px** |
| 59 / 34 (제대로 오는 기기) | `min(102, 62)` → **62px** |
| 20 / 0 (홈 버튼 아이폰) | **20px** — 달라지는 것이 없다 |

`html.ios-app` 은 `index.html` 의 인라인 스크립트가 **iOS + 홈 화면 앱일 때만** 붙인다.
브라우저와 안드로이드는 이 규칙에 걸리지 않는다 (안드로이드는 env 를 제대로 주므로 건드릴 이유가 없다).

재어 보면 전투 화면이 이렇게 내려온다 — 물약칸이 상태바(59px) 아래로 완전히 빠진다.

```
상단바 62~141 · 물약칸 70~97 · 메뉴 103~135 · 전투 무대 141~
```

관리자 모드 → 이 기기 정보의 **표시 모드**에 `iOS 앱 보정` 이 붙는지로 확인할 수 있다.

### v1.5.2 — 아이폰에서 상단 메뉴(☰)가 안 눌리던 문제

아이폰 홈 화면 앱에서 **오른쪽 위 ☰ 를 눌러도 아무 반응이 없었다.**
브라우저(폰·태블릿·컴퓨터)에서는 멀쩡히 열려서 한참 헤맸다.

**원인** — 스크린샷을 픽셀로 재어 보니 ☰ 가 화면 위에서 **37~65px** 자리에 있었다.
다이내믹 아일랜드 기기의 상태바는 **59px** 이다. 버튼이 상태바 밑에 깔려 있었고,
그 자리의 탭은 iOS 가 가져간다 (상태바 탭 = 맨 위로 스크롤). 그래서 게임까지 오지 않았다.

`apple-mobile-web-app-status-bar-style=black-translucent` 로 설치된 아이콘에서
`env(safe-area-inset-top)` 이 실제 상태바보다 작게 오는 것이 화근이었다 (약 30px).

**고친 방법** — 홈 화면 앱일 때 위쪽 여백에 **바닥값**을 둔다.

```css
@media (display-mode: standalone), (display-mode: fullscreen) {
  :root { --safe-t: max(env(safe-area-inset-top, 0px),
                        calc(env(safe-area-inset-bottom, 0px) * 1.7)); }
}
```

아래 홈 인디케이터가 있는 기기(노치·다이내믹 아일랜드)면 `34 × 1.7 ≈ 58px` 이 되어
상태바를 넘어선다. 인디케이터가 없는 옛 기기는 아래가 `0` 이라 이 식도 `0` — 아무 영향이 없다.
브라우저에서는 이 미디어 쿼리 자체가 걸리지 않는다.

> `black-translucent` 를 `black` 으로 바꾸는 길도 있지만 그러지 않았다. 그 값은 홈 화면에
> **추가할 때** 읽혀서 이미 설치한 아이콘은 그대로이고, 새로 설치한 쪽은 iOS 가 비워 주는
> 자리와 CSS 여백이 겹쳐 위가 두 배로 빈다.

* 메뉴 버튼을 30×28 → **34×32** 로 키웠다.
* 관리자 모드 → **이 기기 정보**에 `표시 모드 · 안전 여백(env → 적용) · 메뉴 버튼 위치`를 적어 둔다.
  같은 일이 또 생기면 그 화면 숫자만 보면 된다 (`js/viewport.js` 의 `safeInsets()` 가 자로 잰다).

### v1.5.1 — 백과사전 상세 설명 · 구체 연출 시간차 · 설정의 백과사전

**1. 백과사전에 긴 설명을 넣었다**

백과사전은 "따로 들어가서 자세히 보는 화면" 이므로 자리를 더 쓰더라도 길게 적는다.

| 파일 | 무엇 |
|---|---|
| `js/data/statehelp.js` | 상태 **118종 전부**의 상세 설명 |
| `js/data/cardhelp.js` | 글만으로는 규칙이 안 보이는 카드 **45장**의 보충 설명 |

> **상세 글에는 수치를 다시 적지 않는다.** 바로 위에 `powers.js` 의 한 줄이, 카드에는 카드 글이 이미 있다.
> 여기에 또 적으면 수치를 고칠 때 반드시 갈라진다 (몬스터 도감과 같은 원칙).
> 상세 글에는 **언제 붙고 언제 사라지는지 · 정확히 무엇에 적용되는지 · 흔한 오해**만 적는다.

용어집에서 이름이 상태와 같은 낱말(조준·중독·완충 …)은 `statehelp.js` 것을 자동으로 끌어다 쓴다 —
사전에 또 적지 않는다. 이름이 겹치는 것(자세 **분노** vs 상태 **분노**)만 사전에 직접 적어 둔다.

백과사전에서 카드를 누르면 `효과 → 자세히 → 용어(+상세)` 순으로 펼쳐진다.
전투 중 길게 누르기는 **짧게 그대로** 둔다 — 거기서는 빨리 보는 것이 목적이다.

이중 시전 : 0ms → 500ms        (번개가 두 번 치는 게 보인다)
턴 종료 패시브 : 왼쪽 구체부터 하나씩
```

* 기다릴 수 없는 곳(피해 처리 도중의 정전기 방전, 전투 시작 유물)은 `channelOne()` 을 쓴다 — 사이를 띄우지 않는 같은 동작.

* UI 쪽의 임시 시차(`index * 0.22초`)는 **뺐다.** 이제 엔진이 사이를 띄우므로 겹으로 밀리면 안 된다.
* `node tools/sim-cards.mjs` 로 캐릭터 4종 × 전 카드 × 강화 전/후 **2904회**를 돌려 회귀를 확인했다.

**3. 설정에서 백과사전**

게임 중 메뉴 ☰ → 설정 안에서도 백과사전으로 바로 들어갈 수 있다.

창조적 AI = 전구
각성 전 = Z Z Z
오메가  = Ω
```

### v1.4.1 — 큰 화면에서도 폰 비율 유지 (태블릿·컴퓨터 레터박스)
이 게임은 **스마트폰 세로 화면을 겨냥해** 만들었다. 태블릿이나 컴퓨터에서 열면 가로가 넓어져 레이아웃이 늘어나 버리므로, **폰에 가까운 비율의 상자 안에만 그리고 양옆을 비운다.**

```css
--app-w: min(100vw, calc(100vh * 0.62), 560px);
--app-h: min(100vh, calc(var(--app-w) / 0.40));
```

| 허용 비율 | 뜻 |
|---|---|
| `0.62` 보다 넓으면 | 양옆을 비운다 (16:9 폰 = 0.5625 → 꽉 참) |
| `0.40` 보다 길쭉하면 | 위아래를 비운다 (21:9 폰 = 0.429 → 꽉 참) |
| `560px` 상한 | 큰 화면에서 폰보다 지나치게 커지지 않게 |

**폰에서는 아무것도 달라지지 않는다.** 어떤 폰이든 `100vw` 가 가장 작아서 상자가 화면을 꽉 채운다. 여백은 아이패드 세로(0.75)부터 생긴다.

> **크기 계산을 js 로 하지 않는다.** js 로 재서 CSS 변수에 심으면 **첫 프레임에 전체 너비로 한 번 깜빡인다.** `min()` 이면 CSS 만으로 같은 값이 나온다. `js/viewport.js` 는 창 좌표가 필요한 몇 곳(툴팁 가두기·관리자 정보)에 쓸 자만 내준다.

**`vw`/`vh` 를 전부 갈아 끼웠다 (10곳).** 상자가 좁아져도 `vw` 는 **바깥 창** 기준이라 따라 줄지 않는다. 데스크톱에서 `calc(3.25vw - 0.9px)` 는 **62px** 이 되어 백과사전 카드가 터진다. 상자의 1%를 가리키는 `--vw` / `--vh` 를 만들어 바꿨다.
```css
--vw: calc(var(--app-w) / 100);
--desc-fs: calc(var(--vw) * 3.25 - 0.9px);   /* 예전 : calc(3.25vw - 0.9px) */
```
> 커스텀 속성은 `calc()` 토큰 그대로 남으므로 `getPropertyValue('--vw')` 로는 px 를 못 읽는다(`NaN`). 실제로 적용됐는지는 **그걸 쓰는 요소의 계산된 크기**로 확인해야 한다 — 회귀 테스트도 그렇게 짰다.

**js 쪽 세 곳**도 창이 아니라 상자를 보게 고쳤다 — 툴팁 가두기(`showTooltip`), 손패 폭 기본값, 관리자 정보의 화면 줄(창 크기와 화면 틀을 따로 보여 준다).

**여백 표시**는 `@media (min-aspect-ratio: 62/100), (min-width: 561px), (max-aspect-ratio: 40/100)` 로 낸다 — 위 `min()` 이 무엇에 걸리느냐와 조건이 정확히 같다. 폰에서는 테두리 1px 도 그리지 않는다.

### v1.3.18 — 엔딩을 한 두루마리로 이어 천천히 흐르게
v1.3.15 는 1장 → 2장 → 3장을 **`display:none` 으로 갈아 끼웠다.** 장면이 툭툭 바뀌어 읽을 새가 없었다. 세 장을 **한 두루마리로 이어 두고 화면이 그 위를 천천히 내려가는** 방식으로 바꿨다.

**이메일 + 6자리 PIN (`accounts:signUp` / `signInWithPassword` / `sendOobCode`)**

**PIN 이 6자리인 이유** — Firebase 의 비밀번호 최소 길이가 6자다. 4자리를 쓰려면 뒤에 무언가 덧붙여야 하는데, 그러면 Firebase 재설정 페이지에서 사용자가 정한 새 비밀번호와 규칙이 어긋나 **PIN 찾기가 깨진다**. 6자리면 그대로 쓸 수 있고, 경우의 수도 1만 → 100만으로 늘어난다.

**입력** — PIN 칸은 `inputmode="numeric"` + 숫자만 필터링(글자를 쳐도 숫자만 남는다) + 자간을 벌려 자릿수를 세기 쉽게 했다.

### v1.3.4 — 클라우드 백업 철회 (v1.3.2 되돌림)
v1.3.2 에서 넣은 Firebase 백업을 **도로 걷어냈다**. 구조적으로 제구실을 할 수 없었다.

**왜 성립하지 않는가**
- 백업이 쓸모 있는 유일한 상황은 **`localStorage` 가 지워졌을 때**다 (사파리 ITP 7일 규칙 등)
- 그런데 익명 사용자를 식별하는 `refreshToken` 도 **같은 `localStorage`** 에 있다
- 지워지면 신원도 함께 사라지고, 다음 실행에 `accounts:signUp` 이 **전혀 다른 uid** 를 발급한다
- 새 uid 의 `backups/{uid}` 는 비어 있고, 예전 백업은 **영영 고아가 된다**
- 토큰만 남고 계정 데이터만 사라지는 경우는 없다 — ITP·데이터 삭제·기기 변경·저장공간 회수 모두 **origin 단위로 통째로** 지운다

재현 (가짜 Firebase 에 신원 발급을 제대로 모델링):

```
백업 올림        → backups/uid1
ITP 가 지움
새 신원 발급     → uid2
읽으려 한 문서   → backups/uid2  (비어 있음)
결과            → 복구 실패, 빈손으로 시작
```

> v1.3.2 때의 검증이 틀렸다. 가짜 서버가 uid 를 고정값으로 돌려줘 신원이 바뀌는 상황을 모델링하지 못했고, "복구된다" 는 통과는 허상이었다.

**제대로 하려면** 진짜 로그인(구글 계정·이메일)이 필요하다. 비밀번호 없이 쓴다는 이 게임의 전제와 어긋나므로 넣지 않는다.

**대신** 기록을 지키는 가장 확실한 방법은 **홈 화면에 추가(PWA 설치)** 다. iOS 는 설치된 웹앱을 ITP 7일 규칙에서 제외한다. `manifest.webmanifest` 는 이미 갖춰져 있다.

**지운 것** — `js/cloud.js` (276줄) · `firestore.rules` · `profile.js` 의 `onProfileChange` 훅 · 계정 화면의 백업 상태 줄 · 저장소에 들어가 있던 Firebase 설정

### v1.3.2 — 계정·전적 클라우드 백업  *(v1.3.4 에서 철회됨 — 아래 참고)*
계정과 전적을 Firebase 에 한 벌 더 떠 둔다. **동기화가 아니라 백업**이다.

**설계 (`js/cloud.js`)**
- **로컬이 언제나 정답** — 클라우드는 복사본일 뿐. 여기서 예외가 밖으로 새지 않도록 전부 안에서 삼킨다
- **SDK 를 쓰지 않고 REST 로 직접 호출** — 빌드 도구·외부 의존 0개 원칙을 지키고, SDK 배포처(`gstatic`)가 막힌 망에서도 돌아간다
- 익명 인증(`accounts:signUp`) → `refreshToken` 만 로컬에 보관, `idToken` 은 메모리에만
- 저장은 `backups/{uid}` 문서 하나에 JSON 한 덩어리. 1 MiB 제한에 닿으면 **오래된 기록부터** 덜어 낸다
- 모든 요청에 **12초 시간 제한** — 응답이 없어도 매달리지 않는다
- 로컬이 바뀌면 **4초 디바운스** 후 업로드. 실패하면 `dirty` 를 남겨 다음 기회에 다시 시도
- 백업 대상은 **계정 목록 + 계정별 전적**. 진행 중인 런은 넣지 않는다 (덩치가 크고 다시 하면 그만)

**복구 규칙**
- **이 기기에 계정이 하나도 없을 때만** 되살린다 (사파리 ITP 가 7일 미사용 시 `localStorage` 를 비우는 경우)
- 계정이 이미 있으면 클라우드로 덮어쓰지 않는다
- 복구 대기는 **최대 4초** — 그 안에 응답이 없으면 그냥 게임을 시작한다

**빠뜨릴 수 없는 구조**
- `profile.js` 의 `commit()` / `Records.add` / `Records.clear` **한 곳에서만** 변경을 알린다 (`onProfileChange`). 호출부에서 백업 갱신을 잊을 수가 없다

**Firebase 쪽 준비물** — `firestore.rules` 참고
- 콘솔에서 **Authentication → 익명(Anonymous) 로그인 사용 설정**이 필요하다 (안 켜져 있으면 `CONFIGURATION_NOT_FOUND`)
- Firestore 규칙은 자기 `uid` 문서만 읽고 쓰도록 제한한다
- `apiKey` 는 Firebase 웹 앱에서 공개를 전제로 한 식별자다. 실제 보호는 위 보안 규칙이 한다

## 9. 테스트용 자원 2배 (`NEOW_SECRET`)

**발동 방법** — 설정 → `관리자 모드`(숫자 4자리) → **자원 2배로 시작** 을 켠 뒤 판을 시작합니다.

> v1.3.16 까지는 시작 보너스 화면의 **네 번째 선택지 아래 아무 표시 없는 자리**(`.choice-secret`, 높이 54px)를 탭하는 방식이었습니다. **v1.3.17 에서 그 숨은 버튼을 없앴습니다** — 관리자 모드가 같은 일을 더 분명하게 하고, 모르고 눌러 판을 버리는 일이 없어집니다. 효과 자체(`NEOW_SECRET`)는 그대로 씁니다.
